\# 情报监测与富化模块技术报告



\## 一、模块概述



\### 1.1 设计目标



本模块面向 AI 安全领域，构建覆盖多源情报的自动采集、去重、富化与存储系统，为下游 RAG 问答模块提供标准化、结构化的安全情报数据，支撑基于大模型的安全问答场景。



\### 1.2 核心指标



| 指标 | 要求 | 实际达成 |

|---|---|---|

| 监测数据源覆盖 | ≥5 类 | 9 类 |

| 采集延迟 | ≤6 小时 | ≤4 小时 |

| 富化维度 | ≥5 种 | 5 种 |

| 富化准确率 | ≥95% | ≥95% |



\### 1.3 模块边界



本模块负责情报的采集与富化，上游为公开数据源，下游为 RAG 问答模块和 LangGraph 总控 Agent。对外提供 4 个 Python 接口，不涉及 RAG 检索、大模型调用与用户问答逻辑。



\## 二、系统架构



\### 2.1 总体架构



采集层 → 去重层 → 富化层 → 存储层 → 服务层 → 可视化层



各层职责：



采集层由 9 个独立采集器组成，覆盖 REST API、RSS、Atom XML 三类协议。去重层基于 `{source}:{原生ID}` 生成唯一键，SQLite 主键冲突自动忽略。富化层实现 5 维富化加评分卡和攻击链可视化。存储层使用 SQLite 单表 items，字段见第七节。服务层对外提供 4 个接口。可视化层为 Streamlit 单页应用。



\### 2.2 数据流



采集器拉取原始数据并归一化为统一字典结构，生成 uid 后写入 SQLite，主键冲突自动忽略。富化管道对每条记录依次执行 5 维处理。服务层暴露查询与富化接口。导出接口将 records 转为 Chroma 格式供下游使用。



\### 2.3 去重机制



不使用 URL 或标题作为去重键，因为同一漏洞在不同源 URL 不同、标题略有差异。改用 `{source}:{原生 ID}` 组合键：NVD 用 CVE 编号，GitHub Advisories 用 GHSA 编号，ArXiv 用论文 ID，RSS 源用 URL。写入时使用 INSERT OR IGNORE，主键冲突静默跳过。



\## 三、数据源设计



\### 3.1 数据源列表



| 编号 | 数据源 | 协议 | 认证 | 典型字段 |

|---|---|---|---|---|

| 1 | NVD | REST API | API Key | CVE、CVSS、CWE、影响版本 |

| 2 | GitHub Security Advisories | REST API | Token | GHSA、CVE、severity、references |

| 3 | Hugging Face Blog | REST API | 无 | title、publishedAt、authors |

| 4 | 安全客 | RSS | 无 | title、link、pubDate |

| 5 | ArXiv | Atom XML | 无 | title、summary、authors |

| 6 | OSV.dev | REST API | 无 | id、aliases、severity |

| 7 | Seebug Paper | RSS | 无 | title、link、pubDate |

| 8 | Exploit-DB | RSS | 无 | title、link、pubDate |

| 9 | Hacker News | RSS | 无 | title、link、pubDate |



\### 3.2 选型依据



NVD 是官方权威漏洞库，结构化程度最高。GitHub Advisories 是 AI 框架漏洞的主要来源，覆盖开源生态。Hugging Face Blog 提供 AI 模型安全最新动态。安全客和 Seebug 是中文安全社区，补充国内视角。ArXiv 提供学术前沿数据，为论文关联富化提供数据源。OSV.dev 由 Google 维护，覆盖 NPM、PyPI、Go 生态。Exploit-DB 是公开 POC 库。Hacker News 提供安全社区动态。



\### 3.3 容错设计



NVD 接口失败时自动降级读取本地缓存。ArXiv 遇到 429 限流时重试 3 次并退避等待。各源独立采集，单个源失败不影响其他源。



\## 四、情报富化详设



\### 4.1 五维富化



\*\*维度 1 论文关联\*\*



使用 Sentence-BERT 模型 all-MiniLM-L6-v2 对漏洞描述与 ArXiv 论文摘要进行向量编码，计算余弦相似度。相似度阈值设为 0.3，超过阈值的论文按相似度降序返回 Top 5。



\*\*维度 2 CVSS 评分补充\*\*



对 NVD 数据缺失的 CVSS 字段，调用 NVD API 按 CVE 号补全 CVSS v3.1、v3.0、v2.0 三级评分。结果本地缓存于 data/cvss\_cache.json，同一 CVE 只请求一次。



\*\*维度 3 POC 检索\*\*



调用 GitHub Search API 搜索 `{CVE-ID} poc` 关键词，按 stars 降序取 Top 3。结果本地缓存于 data/poc\_cache.json。



\*\*维度 4 资产识别\*\*



基于 40 多个 AI 框架关键词表（PyTorch、TensorFlow、Transformers、LangChain、vLLM 等）进行正则匹配，同时提取版本号。输出 assets.frameworks 和 assets.versions。



\*\*维度 5 攻击链推理\*\*



定义 5 个攻击链模板：提示词注入、模型盗取、数据投毒、供应链攻击、越权访问。每个模板包含关键词列表和标准攻击步骤。对漏洞描述进行关键词匹配，命中则输出对应攻击链及其步骤序列。



\### 4.2 创新点



\*\*创新 1 情报评分卡\*\*



综合评分公式：



```

score = 0.4 × cvss\_norm + 0.2 × has\_poc + 0.2 × asset\_match + 0.2 × freshness

```



其中 cvss\_norm 为 CVSS 分数归一化到 0 到 1，has\_poc 表示是否有 POC，asset\_match 表示是否匹配 AI 资产，freshness 为 7 天内线性衰减。输出 0 到 100 分，分档 CRITICAL、HIGH、MEDIUM、LOW。



\*\*创新 2 攻击链可视化\*\*



将攻击链转为 Mermaid flowchart 语法，输出 mmd 文件，可嵌入 Markdown 或 Web 页面渲染。



\*\*创新 3 语义搜索\*\*



基于 Sentence-BERT 对情报库构建向量索引，支持自然语言查询。相比关键词匹配，能识别语义相关但字面不同的记录。



\### 4.3 富化管道



enrichment/pipeline.py 提供 enrich(item) 方法，对单条情报依次执行 7 个处理步骤：论文关联、CVSS 补充、POC 检索、资产识别、攻击链推理、评分卡计算、攻击链可视化。每步都有 try-except 保护，单步失败不影响后续步骤。



\## 五、关键技术



\### 5.1 缓存机制



CVSS 缓存位于 data/cvss\_cache.json，key 为 CVE 号。POC 缓存位于 data/poc\_cache.json，key 为 CVE 号。向量缓存位于 data/embeddings.npy 和 data/embeddings\_meta.json。命中缓存时直接返回，避免重复调用外部 API 触发限流。



\### 5.2 向量计算



使用模型 all-MiniLM-L6-v2，输出维度 384，本地 CPU 推理，无需 GPU。应用于论文关联和语义搜索。



\### 5.3 定时监测



基于 APScheduler BlockingScheduler，NVD 每小时执行一次，其他 8 源每 4 小时执行一次。调度器独立进程，不与主程序耦合。



\### 5.4 增量同步



SQLite 表 sync\_state 记录各源最近同步时间、运行次数、错误次数，为后续增量采集提供依据。



\## 六、性能测试



\### 6.1 采集性能



9 源全部跑通，累计入库记录 319 条。单源采集耗时 2 到 8 秒，NVD 因 API 限流较慢。全量采集一轮耗时约 30 秒。



\### 6.2 富化性能



单条富化耗时小于 2 秒（含缓存命中）。首次富化因需调 API，耗时约 8 到 15 秒。第二次起走缓存，耗时小于 100 毫秒。



\### 6.3 检索性能



语义搜索 319 条数据，响应时间小于 3 秒。向量计算 319 条耗时约 2 秒。SQL LIKE 查询小于 100 毫秒。



### 6.4 数据分布

- 总情报数：326 条
- 风险等级分布：
  - CRITICAL：0
  - HIGH：0
  - MEDIUM：18（5.5%）
  - LOW：188（57.7%）
  - UNKNOWN：120（36.8%）
- 无 0.0 分误判

**说明**：UNKNOWN 表示无法评估（无 CVSS、无 POC、无 AI 资产、发布时间超 7 天），与 LOW 明确区分。

\## 九、与下游模块对接



\### 9.1 与 RAG 问答模块对接



下游调用 export\_for\_chroma() 获取全部情报的 Chroma 格式，通过 chroma\_collection.upsert() 写入向量库。检索时基于 document 字段进行语义匹配，metadata 字段用于答案的证据引用。



\### 9.2 与总控 Agent 对接



总控调用 collect\_vulnerabilities() 触发采集，调用 search\_vulnerabilities() 做检索，调用 enrich\_vulnerability() 做单条深挖。

pip install -e git+https://github.com/{用户名}/intel-monitor.git#egg=intel-monitor
